# 通用任务验收修正（本地候选）

通用运行时应管理任务的持久状态和续跑，验收条件应来自用户目标。旧实现把交易研究的方法写成全局规则，这是职责边界错误：普通 `edge AI` 任务也会被要求提出多个交易假设、补齐基线实验和 no-edge 归因。

## 本轮改动

- 默认 gate 不再根据 `edge`、`strategy`、`hypothesis` 等词选择领域流程。强制假设数量、基线实验、no-edge 成功路径和基础设施优先级规则已退出执行逻辑。
- 外部来源和产物不是所有任务的共同前提。写作等文本任务可以由完成评估确认交付，无需创建无关文件、寻找外部来源或做实验。
- `GoalContract` 保存结果、验证说明、约束、边界、停止条件，以及可选的 `evidence_requirements`。仅显式要求的证据类型会阻塞完成。
- Critic 提供进展、计划健康度和下一步建议；不再合并领域假设、交易归因或研究充分性，也不能改写目标、成功定义或任务合同。
- 工具账本的投影不再依赖最终响应出现文件路径或验证关键词。
- 去掉“助手说全部完成且调用过验证工具，就覆盖 Judge”的捷径。完成仍需要 Judge 对用户目标的确认及合同要求的证据。

## 当前默认检查

| 检查 | 含义 | 是否阻塞完成 |
| --- | --- | --- |
| G1 | 用户请求的结果存在 | 是 |
| G2 | 已记录外部来源的真实出处 | 否 |
| G3 | 显式合同要求的证据类型存在 | 仅合同明确要求时 |
| G4 | 完成评估确认用户目标已满足 | 是 |

G3 检查证据类型是否存在，不能证明其与任务相关或内容正确。Judge 仍需检查结果是否符合全部用户要求。自然语言中的验证要求也必须由 Judge 评估；运行时不会通过关键词猜测一套领域验收策略。

结构化合同目前是运行时 Python API；本轮未增加聊天命令的合同编辑界面。例如：

```python
manager.start(
    "session-id",
    "修改解析器并运行相关测试",
    contract={
        "outcome": "解析器正确处理新格式，相关测试通过",
        "constraints": "保留已有格式支持",
        "evidence_requirements": ["artifact", "verification"],
    },
)
```

支持的证据类型为 `artifact`、`verification`、`external_source`、`tool_result`、`human_acceptance`。助手或 Critic 的自报不满足这些要求。人工验收使用可信宿主写入的 `human_input` 证据；本轮未提供新的人工验收命令。

领域方法应由用户指令、任务合同或明确选择的 skill 提供。例如，用户可以要求交易研究比较若干策略，但运行时不能把这个任务的要求提升为其他任务的默认前提。本轮没有实现自动领域识别或领域插件框架。

## 旧状态兼容

加载和评估时，旧 `SG-1..SG-4` gate 移入 `retired_gates`，不再参与阻塞、完成或续跑决策。退役时清除关联的旧行动建议和惯性状态。重复加载不会重复归档，也不会重新生成它们。

旧假设组合、no-edge 报告、推断意图和成功定义等字段保留序列化兼容，不再作为当前评估提示的验收依据。助手自报的证据及旧假设证据不进入工具/人工证明展示。事件和工具记录继续保留。

## 开发基线与边界

本地分支 `codex/generic-runtime` 基于服务器插件提交 `d306e42b52e8ce123c38d44bdf865abcbefee09b`，并纳入已保存的服务器 `command.py`、`plugin.py` 接口兼容补丁。持久化 outbox、CAS、用户抢占及压缩关联仍沿用此基线。

本轮只修正任务验收和相关提示/投影。回合顺序重放幂等性、clear 后会话复用、Windows PID 检查、两套 controller 路径和宿主适配集中化仍是已知后续工作，不能据此宣称整体架构已经重构完成。
