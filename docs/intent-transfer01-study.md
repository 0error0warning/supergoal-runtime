# 意图与有效工作的四组对照

2026-10-06，独立于此前归档批次。研究问题是：保留原始请求、显式区分假设、按信息缺口
选择行动，并逐项绑定真实观察，能否减少无效工作、改善最终交付。代码和控制规则不包含
任务名称、领域关键词或参考答案分支。完整方法与原始论文/项目链接见[冻结方案](../experiments/public_benchmarks/INTENT-TRANSFER01.md)。

## 候选实现

新增 `work_policy.py` 保存完整请求，为模型提供直接执行、检查上下文和围绕决策研究的指导。
模型生成的简报只作为工作记忆，每条明确要求必须能追溯到请求原文；未知偏好与可逆默认
单列为假设。原始要求仍有优先权。模型审查必须逐项提交本次工具输出证据，并绑定当前产物。

运行时将“尚可补做检查”的未知与缺少观察能力、需要用户信息的未知分开。只有契约允许且
验收结果明确标记 `retryable=true` 的未知才会继续。继续执行不意味着通过，也不会重置预算。
这一分类主要防止没有新信息的重复实现，不能自动判断一个模型检查在语义上是否充分。

正式 v2 插件已接入可选工作指导和未知处理；完整的简报生成、隔离模型审查和共享请求预算
由实验适配器连接。自然语言目标尚未通过这一新流程接入日常插件入口，生产部署未改变。
实际可用方式与边界见[工作策略说明](intent-and-evidence-policy.md)。

## 迁移结果

32/32 次登记试验全部结束。终端原始结果如下；每组只有六个不同任务、各运行一次。

| 分组 | 端到端通过 | 物理请求 | 输入 token | 输出 token | 额外执行轮数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原生 Hermes | 6/6 | 89 | 789,066 | 19,731 | 0 |
| 简单重发目标 | 5/6 | 155 | 2,048,349 | 28,596 | 30 |
| 原 SG | 5/6 | 116 | 748,189 | 21,860 | 0 |
| 新证据策略 | 5/6 | 138 | 1,166,009 | 39,115 | 0 |

新策略比原生多用约 55% 请求，没有提高这批任务的原始通过数。原 SG 在压缩包任务
达到求解时限，按端到端失败保留；重发组的失败是 `fix-git`；新策略的失败是下文所述
速度测试。不同组随机生成的方案和运行条件仍限制归因，不能由单次结果断言某种架构
普遍更好或更差。所有单元的 token 回执完整；没有费用账单，因此不推算美元成本。

新策略的六个终端任务都只执行一轮。三个最终产物通过独立测试的任务仍被保留为未知，
原因均为审查格式/证据校验未通过；这些不是有证据的任务失败判定。八个新策略运行中，
两个简报在格式修复后仍不可解析，回退到完整原始请求。形式化的解释与审查本身也需要验证。

研究任务四组各交付两份报告，请求分别为原生 18、重发 48、原 SG 42、新策略 40。
独立模型内容诊断仅 **1/8** 通过全部格式和原文引文校验：新策略的 `014` 被评分器判为
请求覆盖 1.0，抽查事实 4 项有来源支持、1 项无法确认。其余七份评分因报告或来源引文
校验失败而保留为未评分。不能据此计算四组研究质量均值或宣称新策略更优。

全部原始输入文件字节保持不变。原生 `014` 在输入目录额外生成了 `user_files/tex.txt`；
原始诊断的整目录一致性字段因此为 false，不应解读为原始 PDF 或语料被改写。

## 已核对的限制与反例

`largest-eigenval` 的新策略给出在线通过，但原始独立评分为 0：27 个测试中，25 个通过，
失败的是 6×6、7×7 两个速度断言。审查器引用的本地运行确实显示通过，不能把这次错误
简单归结为虚构观察。它说明真实观察也可能不足以保证另一运行条件下的定量结果。
事后为四组最终产物各登记固定五次串行离线诊断，在主试验与研究评分均停止后运行，
沿用官方 27 项测试和原 CPU/内存限制；**20/20 次全部通过**。这支持结果对运行条件
敏感，不能确定是哪个条件造成了原始失败，也不能将串行复测改写为主试验成绩。
原始 0 分和在线通过记录同时保留。该反例不能单独证明新策略的数值实现更差。

`fix-git` 的重发组最终两个文件散列不符合官方要求；执行了六轮并不保证更完整的交付。
没有逐轮独立评分，不能声称第一轮已经正确，或将失败确定归因于后续轮次。

研究任务 `024` 的新策略审查曾提交拼接出的短语和无法核对的文件列表行。修复后仍有
引文不在本次观察中，因此被记录为未知。这说明程序化来源检查能挡住这类完成声明；
它既不证明报告内容错误，也不证明其他有真实引文的结论正确。

## 验证范围

冻结候选在隔离 GCP 上使用真实固定 Hermes 源码运行完整测试：251 项通过，0 失败、
0 跳过；108 个运行时、实验适配器和测试文件与冻结散列匹配。测试没有模型调用，也
没有切换生产 Gateway。测试传输的前两次准备失败分别是目录插件入口命名错误和漏传
基础设施模块；失败日志与修正后的完整检查分开保留。

本地 Windows 的宿主独立回归为 225 passed、7 skipped、3 deselected；另有三项新分析器
回归通过。省略项涉及实际 Hermes 或 POSIX 环境，PID 用例需在 Linux 验证。此前本地整套
尝试因缺失 Hermes 和该 PID 边界失败/中断，未计作通过。Ruff 与 wheel 构建通过。

最新上游 Hermes 的兼容 CI 仍受旧通用 ABI 补丁冲突限制；上述实际宿主验证只适用于固定
的自定义 v0.21.3 源码，不能扩展为兼容所有上游版本。

结束后的审计确认 32 个独立控制器、任务原文、源码、CPU/内存和全部角色的请求预算
一致。研究任务的初始镜像 ID 随 Docker Compose 项目标签变化；文件层和其余执行配置
完全一致。最初按完整镜像 ID 比较得到的告警，以及进一步核对的通过收据均保留。

证据已取回本地并校验。GCP 于北京时间 21:27:21 停止，持久磁盘保留，实验模型隧道
关闭；生产 Hermes Gateway 和 Dashboard 的观测状态均为运行中。停机收据和分析源码
见[衍生结果清单](../experiments/results/intent-analysis01/manifest.json)。

研究内容诊断使用执行前冻结的请求条目、隐藏分组名、独立新会话，并核对报告/来源原文
引文。评分器仍是同一基础模型，最多抽查五个事实，来源节选有长度限制；无效评分保留
为未评分。这不是官方 DR3-Eval 分数、专家审核或事实错误率估计。

这批任务不检验交互中恢复私人偏好、开放网络资料检索、跨天无人监督工作，也不测量
用户纠正与监督次数。代码接入、单元测试、更多 token 和有格式的检查表不能替代这些能力证据。

## 对产品方向的判断

保留已经验证的状态控制、来源校验和观察范围分类，把新工作指导作为可选能力。
本轮没有足够证据把完整解释器—执行器—审查器流程设为所有任务的默认路径。
后续能力研究应直接测量需求澄清与变化、实际行为覆盖，以及人工纠正次数；研究评分器
本身也需要独立校准。用户仍不应为了使用自然语言目标而被迫先写完一套可信评分程序。
