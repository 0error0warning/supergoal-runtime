# 意图理解、研究与证据工作策略

2026-10-06 的候选实现。目标是减少用户反复补充、催促和纠正完成判断的负担。
`intent-transfer01` 对照研究单独检验其效果；代码存在、提示更详细、运行时间更长都不算效果证明。

## 从用户要求到下一步行动

原始请求始终保留。工作简报将用户明确要求、从上下文得到的事实和待验证假设分开；
每项明确要求必须引用原文的连续片段。无法在原文中找到的引用会使简报校验失败，
经过一次受限格式修复后仍失败则回退到完整原始请求。引用存在只证明来源可追踪，
不能证明模型正确理解了该要求，也不能证明没有漏项。

通用策略按缺少的信息选择行动，不按任务名称或领域关键词套固定流程：

| 当前情况 | 策略要求 |
| --- | --- |
| 目标明确，做法和上下文足够 | 直接执行可逆步骤 |
| 本地状态或实际行为不明 | 先检查文件、工具输出和可重现行为 |
| 方法需要选择，或结果依赖当前外部知识 | 围绕具体决策查原始论文、官方资料和实现，再落到实验或改动 |
| 缺少只有用户知道、且会实质改变结果的信息 | 提出具体问题，同时继续独立工作 |

研究没有篇数配额。检查点要记录资料解决了哪个问题、候选方案及限制、为何选择下一步，
并在新观察与原判断冲突时重新查证。用户未说清的偏好留作假设；假设不能增加权限，
也不能把用户明确保留给自己的工作变成执行器的前置条件。

这些是模型遵循的工作指导，不是一个已获验证的自动路由分类器。研究适配器会记录
`direct`、`inspect`、`research` 的选择及理由，但不会因一个路由标签而强制搜集固定数量的资料。

## 以当前产物的观察检查完成

实验审查器先检查完整原始请求，再逐项审查工作简报。每项给出 `pass`、`fail` 或
`unknown`，明确缺失条款，并引用本次审查实际工具输出中的连续文字。程序检查条目
是否完整、引用是否存在，并把证据绑定到当前产物镜像。执行器的完成声明不能充当工具证据。

这层检查阻止漏交简报中的审查条目、提交不存在的引用，以及错用其他产物的观察。
它不能程序化地证明简报覆盖了完整用户意图，也不能判断一句真实工具输出
是否在语义上足以支持结论；模型可能运行了不充分的测试，或误解了真实输出。
因此，独立隐藏测试与研究质量诊断仍在执行结束后另行运行。

`unknown` 的原因决定是否还有有效工作：

| 原因 | 行为 |
| --- | --- |
| `unobserved`：还未做一个可行的本地检查 | 在契约允许且审查结果明确 `retryable=true` 时继续 |
| `environment`：审查环境看不到所需状态 | 保留未知及所缺能力，停止无效的重复实现 |
| `user_input`：依赖不可取得的私人信息 | 保留未知，交还需要用户决定的事项 |
| 审查格式或证据校验失败 | 保留错误和未知，不自动记为成功或继续重复 |

例如，文件系统快照无法复制正在运行的 HTTP 服务、内存和挂载卷。快照里没有进程，
不能证明原执行环境的服务没有启动。处理方式应是取得正确观察能力，而非再次重建同一批文件。
`unknown` 仍消耗已经执行的轮数；重复提交同一结果不会增加派工或重置预算。

## 正式插件入口可以使用什么

在 [v2 契约](v2-plugin-and-acceptance.md) 中可以显式加入：

```json
{
  "work_policy": "evidence-v1",
  "verification_unknown": "continue"
}
```

这是两个可选字段，不是完整契约。原有 `outcome`、`criteria`、`checks`、校准样例和
预算仍须提供。`work_policy` 会把上述通用工作指导加入实际派工信封，随契约保存并在
重启后保留；修订以新契约的字段为准。省略时不增加指导。`verification_unknown` 默认是 `stop`；选择 `continue`
仍要求可信验收结果明确包含布尔值 `retryable=true`，不会把未知改成通过。

生产候选的 v2 入口仍使用操作者配置、校准的检查器。自然语言简报生成、模型逐项审查、
隔离快照和共享模型请求预算，当前由 `experiments/public_benchmarks/evidence_agent.py`
连接成实验流程。它们尚未成为日常 `/supergoal start <自然语言>` 的自动执行流程，
也没有部署到生产 Hermes。不能把新增指导描述成已经交付的通用意图理解产品。

## 本轮如何检验

先用两个开发任务发现并修复格式不稳定和观察范围不匹配，再冻结源码、任务、环境、
顺序和研究评分规则，运行六个未用于开发的终端任务及两个研究任务。
四组分别是原生 Hermes、简单重复目标、原 SG 审查策略和新证据策略。
每组共享相同模型、工具和请求上限，并记录真实请求、token、时间和角色开销。

终端结果使用独立任务测试；研究报告的存在只表示交付了文件。研究内容由预先冻结的
请求条目和匿名来源检查另行诊断，同模型评分及抽样局限必须随结果报告。
这次固定资料集研究不验证开放互联网检索，也不验证交互中恢复私人偏好、跨天工作
或用户监督次数的下降。详细方案与来源见 [冻结研究方案](../experiments/public_benchmarks/INTENT-TRANSFER01.md)。
