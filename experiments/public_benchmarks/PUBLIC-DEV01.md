# Terminal-Bench 公开任务开发试验：public-dev01

2026-10-05；这是评测适配器的探索性开发试验，不是已完成的正式消融结论。所有试次必须保留，装置失败与任务失败分开。之后若修改代码，创建新候选编号，不覆盖原试次。

## 固定设置

- 官方任务源：Terminal-Bench 2.1，commit `7131e4375048a0e408a8fb404b5f499d726b695b`；原始 instruction、镜像、最终 tests 不改。Harbor `0.24.0`，Docker `26.1.5`，`fuse-overlayfs`。
- 主机：Tailscale `grok-bot`，8 CPU / 16 GB；并发 1。各任务保留官方 1 CPU / 2048 MB 限额和原始 agent/verifier 超时。Docker 后端没有独立磁盘配额，控制器在宿主剩余磁盘不足 15 GiB 时中止并记录环境资源失败。
- 执行器：真实 Hermes `0.21.3` 的私有生产源码快照，2126 个 Python 文件散列与原快照一致；新环境使用 Python `3.13.5` 和该源码 `uv.lock` 的核心依赖。生产环境的 Python 为 `3.11.16`，这一差异须在报告中保留。
- 模型：仅 `devin/swe-2` Responses API；每试次最多 96 个实际上游请求，每请求输出上限 6000 tokens。所有续跑、审查和 SDK 重试共享请求预算和任务墙钟时间；token 用量另行实测，本轮不声称设置了总输入 token 硬上限。模型价格不作为完成质量的证据。
- 工具：Hermes 原有 terminal / file，经插件环境接口连接当前任务容器。无本机 Docker，控制器/密钥/隐藏 tests 不挂入执行器。文件工具和超时行为先做真实无模型检查。

## 任务与比较

候选任务：`cancel-async-tasks`、`db-wal-recovery`、`raman-fitting`、`schemelike-metacircular-eval`、`configure-git-webserver`、`multi-source-data-merger`。选择依据为声明资源、任务类别和环境预检，不依据模型成绩。每个任务一个试次/组；不是增加同类随机种子。正式运行清单与顺序写入 registration JSON 后冻结。

分组：`native`（原生 Hermes 单次可用全部预算）；`repeat_goal`（仅重发原始目标）；`sg_v2`（持久状态及独立在线审查）；`sg_no_context`（去掉续跑中的持久状态补充）；`sg_no_review`（去掉在线审查，停止状态明确为未验证）。最多 6 个外层执行轮次；单次 Hermes 执行没有人为缩小到几步，仍可使用全部剩余请求预算。

公开基准适配器使用 v2 的真实 SQLite 内核，但不是网关插件的端到端部署测试。其新增的 SWE2 在线审查器与日常插件的校准脚本验收不同，不能借用后者的验证结论。审查器在只读的任务快照中用同一组工具核查原始要求，最多 16 次模型请求，临时文件仅允许写 `/tmp`。快照不包含隐藏 tests；原任务不接受审查器修复。LLM 审查仍可能误判，最终通过与否只以之后运行的官方 verifier 为准。

先运行连接/适配开发样本，验证模型、工具和评分链路；没有先验正负样本校准或足够任务数时，不称该在线审查器已经可靠。机制未触发或各组全通过时，明确报告没有证明收益。初期开发数据不能当作未经观察的保留测试集。

## 记录与排除

每个试次保存模型请求收据、实际 token、执行/审查轨迹、容器资源、源码散列、镜像 ID、内核事件、官方 grader 原始日志和得分。官方 grader 依赖下载失败时，即使 Harbor 写出 reward 0，也标为评分装置失败，不据此判定模型能力；保留原始零分。任何复评或环境重试均使用新编号并关联原试次。

Tailscale 模型隧道当前经过本机转发，主机休眠或断网会影响实验。它不涉及本机容器，但还不是完全脱离本机的长期执行方案。跨天实验开始前须解决隧道独立运行与控制器恢复，不能把当前短试次称为跨天自治证据。
